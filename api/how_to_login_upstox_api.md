# How to Authenticate with the Upstox API

Complete guide to Upstox OAuth authentication, as implemented in `upstox_login.py`. Read this before using the Upstox API in any project — an AI agent must understand the token lifecycle, not just copy a call.

---

## 1. TL;DR

```python
from upstox_login import login

token = login()               # returns access token string (or None)
```

- One function call. Reads credentials from `upstox.json` (next to the module by default).
- Automates the full login: OTP → TOTP → PIN → OAuth → access token.
- Falls back to manual browser copy-paste if automation fails.
- Saves the new token back into the config file on success.
- Call this only when you need a fresh token. Most calls just use the stored token.

---

## 2. How Upstox Authentication Works (the model)

Upstox uses **OAuth 2.0 authorization-code flow**. No long-lived passwords are ever used against the trading API.

```
[your app] --api_key + redirect_uri--> [Upstox login page]
[user logs in with phone + OTP + TOTP + PIN]
[Upstox] --authorization code (in redirect URL)--> [your app]
[your app] --code + client_id + client_secret--> [token endpoint]
[Upstox] --access_token--> [your app]
[your app] --access_token (Bearer header)--> all API calls
```

Key facts:

- **Access token**: short-lived (~24 h in Upstox's case, but treat it as ephemeral). Sent as `Authorization: Bearer <token>` on every request. Generated by the API server; you cannot mint one yourself.
- **API key / API secret / redirect URI**: long-lived, come from the Upstox dashboard when you register an app. Never change unless you rotate them.
- **Authorization code**: single-use, obtained only through a successful login page interaction. Exchanged for the access token within minutes.
- **There is no true refresh-token grant.** To get a new token you re-run the whole login flow. So "refreshing" = re-authenticating and swapping the new token in.

The practical consequence: **your code must tolerate the token expiring mid-run and must re-login automatically.** See §6.

## 3. Prerequisites (one-time, in the Upstox dashboard)

1. Register a developer app at [Upstox Developer Dashboard](https://dashboard.upstox.com/app/).
2. Copy its **API Key** and **API Secret**.
3. Set a **Redirect URI** — Upstox only hands out auth codes on URLs you whitelist here. `http://localhost:8080` is the common choice for local dev; register exactly what you put in config.
4. Note your **mobile number**, **PIN** (the trading PIN), and **TOTP secret** (the 16-char base32 key you use with a TOTP app like Google Authenticator). These are needed only for the automated service-login flow.

No dashboard access to Upstox → no API. Everything else is code.

## 4. Credentials: the config file

`login()` reads a JSON file with credentials under an `upstox` key. Default path: `upstox.json` in the same directory as `upstox_login.py`.

```json
{
  "upstox": {
    "api_key": "e08f8588-...",
    "api_secret": "at2s0e0h7p",
    "redirect_uri": "http://localhost:8080",
    "mobile_number": "8620906459",
    "pin": "990386",
    "totp_secret": "QF5BDYOLOBT6MMF4J4TROGWZUF4L7ZKN",
    "access_token": "eyJ0eXAiOiJKV1QiLC..."
  }
}
```

| Field | Required | Purpose |
|---|---|---|
| `api_key` | yes | App client ID |
| `api_secret` | yes | App secret, exchanged for the token |
| `redirect_uri` | yes | Must match dashboard whitelist |
| `mobile_number` | for auto-login | SMS/OTP account |
| `pin` | for auto-login | Trading PIN (2FA step) |
| `totp_secret` | for auto-login | TOTP base32 secret |
| `access_token` | cached | Current token, written back by `login()` |

**Security:** this file is a live credential store. Do not commit it, do not log it, do not send it to external services. If the app uses token-sync to a GitHub repo (§8), that repo's write access is as sensitive as the token itself.

## 5. The login flow, step by step

`login()` in `upstox_login.py`:

```
login(config_path=?, **credential overrides)
  1. Load creds from config file
  2. Apply any explicitly-passed overrides
  3. Validate api_key/api_secret/redirect_uri present
  4. If mobile_number + pin + totp_secret all present:
        try automated service login  (_auto_login)
  5. If no auth code yet:
        manual browser fallback      (_manual_login)
  6. Exchange code for access token  (_exchange_code)
  7. Save token into config file     (_save_token)
  8. Return token (or None)
```

### Step 4a — Automated service login (`_auto_login`)

This drives Upstox's web login programmatically. It is a **simulated browser session**; each step must succeed in order:

1. **Open the authorization dialog** — GET the OAuth dialog URL with `response_type=code&client_id&redirect_uri`. Follows redirects to `login.upstox.com`, parses `user_id`, `client_id`, `user_type` from the landing URL.
2. **Generate OTP** — POST to `service.upstox.com/login/open/v6/auth/1fa/otp/generate` with the mobile number. Gets a `validateOTPToken`.
3. **Verify TOTP** — compute the current 6-digit code from the TOTP secret (`pyotp.TOTP(secret).now()`), POST to `/v4/auth/1fa/otp-totp/verify`. (The SMS OTP is never actually delivered; the TOTP *is* the OTP — same challenge slot.)
4. **Submit PIN** — base64-encode the PIN, POST to `/v3/auth/2fa` with the internal redirect URI.
5. **Approve OAuth** — POST to `/v2/oauth/authorize` with `userOAuthApproval: true` and the same `requestId`. Response contains a `redirectUri`.
6. **Extract auth code** — parse the `code` query parameter out of that final redirect URI.

Every response status and field is checked; a failure at any step returns `None` and falls through to manual login.

### Step 4b — Manual fallback (`_manual_login`)

Prints the auth URL and prompts:

```
Paste the 'code' parameter from the URL here: <user pastes>
```

The user logs in in their own browser, and the page redirects to `redirect_uri?code=...`. Paste just the `code` value. Any non-empty input is accepted and passed to the exchange.

### Step 5 — Token exchange (`_exchange_code`)

POST the auth code to `https://api.upstox.com/v2/login/authorization/token` as form-encoded:

```
code=<auth_code>
client_id=<api_key>
client_secret=<api_secret>
redirect_uri=<redirect_uri>
grant_type=authorization_code
```

Success → `{"access_token": "..."}`. This is the token used everywhere.

### Step 6 — Persist (`_save_token`)

Rewrites the config file, setting `upstox.access_token` to the fresh token. So after a successful `login()`, the next `login()` may not even be needed.

## 6. Token lifecycle in your project

**Validate before you trust the stored token.** A cached token can be expired or invalidated.

```python
import requests

def token_valid(token):
    resp = requests.get(
        "https://api.upstox.com/v2/user/profile",
        headers={"Accept": "application/json",
                 "Authorization": f"Bearer {token}"},
        timeout=10)
    return resp.status_code == 200

token = cached_token
if not token_valid(token):
    token = login()          # re-authenticate, auto-saves to config
```

**Handle 401 / `UDAPI100050` on every API call.** Upstox returns these when the token is stale. The robust pattern (as in `upstox_client.py`):

```python
response = requests.request(method, url, headers=headers, **kwargs)
if response.status_code == 401 or error_code == "UDAPI100050":
    if login():                      # get a new token
        headers["Authorization"] = f"Bearer {new_token}"
        response = requests.request(method, url, headers=headers, **kwargs)
```

That is the whole game: **one login per session, auto-retry once on token expiry, never store tokens in code.**

## 7. Using it in another project

Copy `upstox_login.py` into your project (it has no dependencies beyond `requests`, `pyotp`, and a `upstox.json`). Three ways to supply credentials:

```python
from upstox_login import login

# (a) Default — reads ./upstox.json next to the module
token = login()

# (b) A different config file
token = login(config_path="creds/prod.json")

# (c) Inline overrides (still need api_key/api_secret/redirect_uri somewhere)
token = login(mobile_number="9999999999", pin="123456", totp_secret="ABC...")
```

Run it standalone to test:

```sh
python upstox_login.py      # logs in and prints the first 20 chars of the token
```

## 8. (Optional) Cross-machine token sync via GitHub

`upstox_client.py` has an extra pattern: after refreshing, it pushes the new token to a private GitHub repo file (`mister-test/api_url`, file `ups_tok.txt`) and, at startup, pulls it back down. This lets multiple machines share one token and keep it fresh. Not required — it's a convenience layer on top of §5-6.

If you replicate it: use a **fine-grained, repo-scoped GitHub token**, treat that token like a password, and only ever sync the Upstox access token — never API keys, secrets, PIN, or TOTP.

## 9. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `Missing Upstox credentials` | config lacks api_key/api_secret/redirect_uri | Fill the file or pass overrides |
| Login page URL not reached / `Failed to reach login page` | API key invalid, or network/redirects blocked | Check key + redirect_uri; try manual login |
| `Login page params missing` | `user_id`/`client_id`/`user_type` absent from redirect | Usually a stale/invalid API key |
| `OTP generation failed` | wrong mobile number, or account not OTP-enabled | Verify dashboard mobile number |
| `TOTP verification failed` | wrong/rotated `totp_secret` | Regenerate secret in dashboard, update config |
| `PIN submission failed` | wrong PIN, or PIN not enabled | Verify trading PIN |
| `OAuth finalization failed` | authorization already approved/revoked on server | Re-run the flow, fresh requestId |
| `Code not found in final redirect` | Upstox changed the response shape | Re-check the last response body in logs |
| Manual login loop / code rejected | redirect_uri mismatch with dashboard whitelist | Register the exact redirect_uri in dashboard |
| Token works, then 401/`UDAPI100050` mid-run | Token expired | Implement §6 auto-refresh |

**Golden rule for agents:** if an Upstox call returns 401 or `UDAPI100050`, do **not** retry the same request with the same token. Re-authenticate with `login()`, update the header, then retry exactly once.
